# Спецификация требований к Layperson Log Viewer

**Версия документа:** 1.2

**Дата:** 3 октября 2026 г.

**Область:** текущая итерация настольного приложения

## 1. Назначение

Layperson Log Viewer предназначен для чтения текстовых файлов журналов и поиска нужных
строк с помощью нескольких фильтров. Пользователь должен иметь возможность скрывать
неподходящие строки либо оставлять их видимыми в приглушённом виде, чтобы сохранять контекст.

Приложение разрабатывается поэтапно. Этот документ фиксирует требования к текущей
итерации с учётом уже принятых решений. Новые возможности включаются в обязательный
объём после отдельного согласования и обновления спецификации.

## 2. Границы текущей версии

- Настольное приложение на C# с интерфейсом Avalonia UI и целевой платформой .NET 10.
- Основная среда использования и проверки — Windows.
- Одно главное окно; добавление фильтров выполняется через диалоговые окна.
- Один загруженный файл за раз; содержимое хранится в оперативной памяти.
- Русский язык интерфейса.
- Поиск буквального текста в отдельных строках; при настройке шаблона времени — фильтрация целых многострочных записей.
- Работа с файлами, в которые другое приложение продолжает запись, если оно разрешает чтение.
- Автоматические тесты логики и интерфейса обязательны.

Поддержка других операционных систем не является критерием приёмки этой итерации.
Использование Avalonia оставляет возможность добавить её позднее.

## 3. Термины

| Термин | Определение |
| --- | --- |
| Строка журнала | Одна физическая строка текстового файла, включая пустую строку. |
| Запись журнала | Строка, совпавшая с шаблоном начала записи, и все строки до следующего совпадения. Текст до первого совпадения образует отдельную запись. Без шаблона каждая строка рассматривается отдельно. |
| Исходный номер | Порядковый номер строки в загруженном файле, начиная с 1. |
| Включающий фильтр | Условие «Показать строки…», разрешающее строки с заданным текстом. |
| Исключающий фильтр | Условие «Скрыть строки…», исключающее строки с заданным текстом. |
| Подходящая строка | Строка, прошедшая совокупность всех правил фильтрации. |
| Отфильтрованная строка | Строка, не прошедшая совокупность правил. |
| Отображаемые строки | Строки, включённые в список журнала, в том числе находящиеся за пределами видимой области прокрутки. |
| Режим контекста | Режим, в котором отфильтрованные строки остаются в списке и показываются серым. |

## 4. Функциональные требования

### 4.1. Открытие и чтение файлов

**FILE-01. Выбор файла.** Кнопка «Открыть файл…» должна открывать системный диалог
выбора одного файла. Диалог должен предлагать расширения `.log`, `.txt`, `.jsonl`
и возможность выбрать файл с другим расширением. Расширение не определяет способ разбора:
содержимое всегда читается как текст.

**FILE-02. Отмена выбора.** Отмена диалога не должна менять загруженные данные,
фильтры и режим отображения.

**FILE-03. Представление строк.** При чтении необходимо сохранять порядок строк,
их исходные номера и текст без символов разделителя строк. Повторяющиеся и пустые строки
не должны удаляться. Завершающий перевод строки сам по себе не создаёт дополнительную
пустую строку. Должны поддерживаться разделители LF, CRLF и CR.

**FILE-04. Кодировки.** Кодировкой по умолчанию должна быть UTF-8. При наличии
метки порядка байтов (BOM) должны распознаваться UTF-8, UTF-16 и UTF-32.
Ошибки декодирования входного UTF-8 должны сообщаться пользователю.
Выбор устаревших кодировок, например Windows-1251, в текущую версию не входит.

**FILE-05. Файлы с продолжающейся записью.** Локальный файл должен открываться
только для чтения, с разрешением совместной записи и удаления/переименования:
`FileShare.ReadWrite | FileShare.Delete`. Просмотрщик не должен удерживать блокировку,
мешающую приложению-источнику дописывать или ротировать журнал. Если источник запрещает
чтение своей блокировкой, просмотрщик должен сообщить об ошибке доступа.

**FILE-06. Обновление данных.** Открытие файла должно загружать прочитанное содержимое
в память. Новые записи после завершения загрузки должны появляться только при повторном
открытии файла. Атомарный снимок файла на конкретный момент времени не гарантируется,
если файл изменяется непосредственно во время чтения.

**FILE-07. Замена файла.** При успешном открытии другого файла его строки должны
заменить ранее загруженные. Текущие фильтры и режим отображения должны сохраниться
и примениться к новым данным. В окне должно отображаться имя нового файла.

**FILE-08. Ошибка чтения.** При ошибке открытия или чтения приложение должно сохранить
ранее успешно загруженные строки и имя файла, показать сообщение об ошибке и позволить
повторить открытие. После успешной новой операции прежнее сообщение об ошибке должно исчезнуть.

### 4.2. Управление фильтрами

**FILTER-01. Создание.** Кнопки «Показать строки…» и «Скрыть строки…» должны
открывать диалог создания фильтра соответствующего типа. Пользователь должен иметь
возможность добавить несколько фильтров каждого типа.

**FILTER-02. Параметры.** Каждый фильтр должен содержать тип, текст для поиска
и признак учёта регистра. По умолчанию регистр не учитывается, в том числе для кириллицы.
В диалоге должны быть поле текста, переключатель «Учитывать регистр» и кнопки
«Добавить» и «Отмена».

**FILTER-03. Допустимый текст.** Пустое значение и значение только из пробельных
символов не должны приниматься. До ввода допустимого значения кнопка «Добавить» должна
быть недоступна. Пробелы вокруг непустого текста должны сохраняться и участвовать в поиске.

**FILTER-04. Вид поиска.** Фильтр должен проверять вхождение заданного текста
в строку. Символы `.`, `*`, `[`, `]` и другие знаки должны трактоваться буквально.
Регулярные выражения не поддерживаются в текущей версии.

**FILTER-05. Применение и отмена.** Подтверждение диалога должно добавить фильтр
и автоматически обновить список строк. Отмена или закрытие диалога без подтверждения
не должны добавлять фильтр.

**FILTER-06. Список фильтров.** Для каждого добавленного фильтра должны отображаться
тип, искомый текст, настройка регистра и кнопка «Удалить». Если длинный текст сокращается
в списке, полный текст должен быть доступен во всплывающей подсказке.

**FILTER-07. Удаление и сброс.** Удаление отдельного фильтра должно сохранять остальные
фильтры. Кнопка «Сбросить» должна удалять все фильтры. Оба действия должны автоматически
обновлять отображаемые строки.

**FILTER-08. Время жизни.** Фильтры должны действовать в пределах текущего запуска
приложения и сохраняться при смене файла. Их сохранение между запусками не требуется.
Допускается создание фильтров до открытия первого файла.

**FILTER-09. Фильтр из выделенного текста.** Контекстное меню текста строки должно
содержать пункты «Показать строки…» и «Скрыть строки…». Выбор пункта должен открывать
диалог соответствующего типа с точным выделенным текстом, включая окружающие пробелы
и знаки препинания. Пользователь должен иметь возможность изменить текст и настройку
регистра перед подтверждением. Фильтр добавляется только после нажатия «Добавить»;
отмена сохраняет прежний набор фильтров. Для пустого выделения, выделения только из
пробелов и во время обработки данных пункты добавления должны быть недоступны.
Кнопки «Показать строки…» и «Скрыть строки…» также должны подставлять выделенный
текст; при нескольких выделениях приоритет имеет последняя активная строка.
Без выделения кнопки открывают пустое поле. При любом способе открытия поле должно
быть редактируемым, получать фокус и выделять подставленный текст для замены вводом.

### 4.3. Правила объединения фильтров

Ниже описан построчный режим по умолчанию. При включении группировки единицей
фильтрации становится запись: совпадение ищется в любой её строке, а решение применяется
ко всем строкам записи. Включающие условия по-прежнему объединяются через «ИЛИ»,
исключающее совпадение имеет приоритет. Поиск текста через границу строк не выполняется.

**MATCH-01. Включающие фильтры.** Если включающих фильтров нет, любая строка
должна проходить включающую часть проверки. Если они есть, достаточно совпадения
хотя бы с одним включающим фильтром: используется логическое «ИЛИ».

**MATCH-02. Исключающие фильтры.** Совпадение хотя бы с одним исключающим фильтром
должно отклонять строку независимо от включающих фильтров. Исключение имеет приоритет.

**MATCH-03. Независимость от отображения.** Правила определения подходящих строк
не должны меняться при переключении между скрытием и показом серым.

Итоговое условие:

```text
Строка подходит =
    (включающих фильтров нет ИЛИ совпал хотя бы один включающий фильтр)
    И
    (не совпал ни один исключающий фильтр).
```

Пример: при включающих фильтрах `ERROR` и `WARN` и исключающем `localhost`
строка `ERROR localhost: connection closed` отклоняется, а `WARN slow response` подходит.

### 4.4. Отображение результата

**VIEW-01. Расположение.** Главное окно должно содержать верхнюю, изначально более
крупную область журнала и нижнюю область фильтров. Между ними должен быть перетаскиваемый
разделитель для изменения высоты областей.

**VIEW-02. Читаемость строк.** Строки должны отображаться моноширинным шрифтом
с исходными номерами. Фильтрация не должна перенумеровывать или менять порядок строк.
Длинные строки должны быть доступны через горизонтальную прокрутку без переноса текста.

**VIEW-03. Вертикальная прокрутка.** В области журнала и в списке фильтров
вертикальные полосы прокрутки должны оставаться видимыми в развёрнутом виде.
Автоматическое скрытие и сужение полос при отсутствии наведения должны быть отключены.

**VIEW-04. Переключатель режима.** Над списком строк должен располагаться переключатель
со следующими состояниями:

- Выключен: «Скрывать отфильтрованные». Отображаются только подходящие строки.
- Включён: «Отфильтрованные — серым». Отображаются все строки; неподходящие строки
  и их номера приглушаются, подходящие сохраняют обычную контрастность.

При запуске должен использоваться режим скрытия. Переключение не должно менять
фильтры, перечитывать файл или повторно вычислять совпадения для неизменных данных.

**VIEW-05. Изменения в режиме контекста.** Добавление, удаление и сброс фильтров,
а также открытие нового файла должны обновлять признак приглушения каждой строки.
Если ни одна строка не подходит, в режиме контекста должны отображаться все строки серым.
Если фильтров нет, все строки должны иметь обычную контрастность.

**VIEW-06. Счётчики.** Строка состояния должна показывать число отображаемых строк,
общее число загруженных строк, число подходящих строк и количество фильтров.
В режиме контекста число отображаемых строк равно общему числу; число совпадений
остаётся результатом применения фильтров.

**VIEW-07. Пустые состояния.** Интерфейс должен различать следующие ситуации:

- Файл ещё не открыт — предложение открыть журнал.
- Открыт пустой файл — сообщение «Файл пуст».
- В режиме скрытия нет подходящих строк — сообщение «Нет строк, соответствующих фильтрам».
- Фильтры отсутствуют — пояснение, что показаны все строки.

Последняя ситуация относится к панели фильтров и может сочетаться с состояниями области журнала.

**VIEW-08. Выделение текста.** Пользователь должен иметь возможность выделять мышью
фрагмент текста в пределах одной строки журнала. Выделение должно работать как для
обычных, так и для приглушённых строк и не должно изменять исходный текст. Правый щелчок
должен позволять использовать выделение для создания фильтра. Выделение не должно
переноситься на другую строку при повторном использовании её визуального элемента.
Выделение единого текстового диапазона через несколько строк в эту итерацию не входит.

При добавлении фильтра кнопками «Показать строки…» / «Скрыть строки…» или через
контекстное меню выделение должно сохраняться, если исходная строка остаётся видимой,
в том числе серым цветом. Отмена диалога также сохраняет выделение. Если строка скрыта,
выделение не должно переноситься на другую строку.

### 4.5. Многострочные записи и шаблон времени

**ENTRY-01. Выбор образца.** Пользователь должен иметь возможность выделить временную
метку в тексте строки и выбрать в контекстном меню «Начало записи по времени…».
Образец должен содержать хотя бы одну цифру 0–9 и находиться в пределах одной строки.
Пункт меню должен быть недоступен для недопустимого выделения и во время обработки.

**ENTRY-02. Правило совпадения.** Шаблон должен сохранять начальную позицию и длину
выделения. Каждая выбранная цифра должна соответствовать любой цифре 0–9; остальные
символы должны совпадать буквально. Например, `2026-10-03 12:34:56` задаёт форму
`####-##-## ##:##:##`. Образец ищется только на выбранной позиции, без поиска по всей строке.
Символы вне выделенного фрагмента не проверяются. Календарная корректность даты не проверяется.

**ENTRY-03. Подтверждение.** Перед применением диалог должен показывать исходный
образец, форму шаблона, позицию первого символа с нумерацией от 1 и число совпадающих
начал записей во всём загруженном файле, включая скрытые фильтрами строки.
Кнопка «Применить» включает новый шаблон; отмена сохраняет предыдущий режим группировки.

**ENTRY-04. Разбиение.** Совпадающая строка начинает новую запись. Последующие строки,
включая пустые, относятся к ней до следующего совпадения. Текст до первого совпадения
должен сохраняться отдельной записью. При отсутствии совпадений непустой файл образует
одну запись; пустой файл не содержит записей. Исходные номера и порядок строк сохраняются.

**ENTRY-05. Фильтрация записей.** При активном шаблоне включающее совпадение в любой
строке должно разрешать всю запись, а исключающее совпадение в любой строке должно
отклонять всю запись. В режиме скрытия запись скрывается целиком; в режиме контекста
все её строки приглушаются. Без фильтров все записи отображаются обычным цветом.

**ENTRY-06. Управление и обратимость.** Над журналом должны отображаться активный
шаблон, его позиция и число найденных начал. Кнопка «Сбросить шаблон» должна возвращать
построчную фильтрацию. Применение, замена и сброс шаблона должны заново вычислять
результат по всем загруженным строкам, сохраняя фильтры и режим скрытия/приглушения.
Шаблон сохраняется при смене файла, но не между запусками приложения.

**ENTRY-07. Индикация.** Начало каждой записи должно визуально отделяться тонкой
линией. При активной группировке строка состояния должна дополнительно показывать
число подходящих записей и общее число записей. Число начал по шаблону может быть
меньше числа записей на одну запись с текстом до первого совпадения.
Если в непустом файле шаблон не найден, должно появляться предупреждение о том,
что весь файл считается одной записью, с предложением заменить или сбросить шаблон.

**ENTRY-08. Ограничения.** Шаблон описывает структуру выбранного фрагмента постоянной
длины и позиции. Переменная ширина префикса, меняющиеся текстовые названия месяцев,
проверка значений даты и произвольные регулярные выражения в эту итерацию не входят.
Пользователь может не включать дробную часть секунды в образец, если её длина меняется.

## 5. Нефункциональные требования

**QUALITY-01. Отзывчивость.** Чтение файла и вычисление результатов фильтрации должны
выполняться вне потока интерфейса. Во время операции должно отображаться состояние
«Обработка…». Действия открытия файла и изменения набора фильтров должны блокироваться
до завершения операции, чтобы исключить конфликтующие изменения.

**QUALITY-02. Прокрутка.** Список журнала должен использовать виртуализацию:
визуальные элементы строк создаются для отображаемой области, а не для всего файла сразу.
Это не отменяет хранение прочитанного текста в памяти.

**QUALITY-03. Сохранность данных.** Приложение не должно редактировать исходный файл.
Фильтрация и приглушение должны менять только представление загруженных данных.
Открытые файловые ресурсы должны освобождаться после чтения, в том числе при ошибке.

**QUALITY-04. Разделение ответственности.** Чтение текста и правила фильтрации должны
быть отделены от элементов интерфейса, чтобы их можно было проверять независимо.
Представление строки и её состояние приглушения должны находиться на уровне интерфейса.

**QUALITY-05. Документация.** Проект должен содержать инструкции запуска, сборки
и выполнения тестов, описание правил фильтрации и структуры кода. При развитии приложения
необходимо объяснять изменения и используемые возможности C# с учётом длительного
перерыва пользователя в работе с этим языком.

**QUALITY-06. Ограничения производительности.** Максимальный размер файла, допустимое
потребление памяти и численные нормативы времени загрузки в текущей итерации не установлены.
Поддержка многогигабайтных журналов не заявляется. Такие нормативы должны быть определены
на согласованных файлах и оборудовании перед реализацией обработки больших объёмов данных.

## 6. Требования к проверке и приёмке

**TEST-01. Автоматические тесты.** Необходимо использовать xUnit для проверки логики
и Avalonia Headless для проверки настоящих элементов интерфейса без вывода окон на экран.
Каждое изменение поведения должно сопровождаться проверками соответствующих сценариев.

**TEST-02. Успешная сборка.** Перед приёмкой должны успешно завершаться автоматические
тесты и сборка Release без предупреждений и ошибок. Количество тестов может увеличиваться
с развитием проекта; фиксированное число не является критерием качества.

проверяются вручную в Windows.

## 7. Возможные следующие итерации

Следующие функции являются кандидатами для обсуждения; сроки и обязательность не установлены:

- Автоматическое чтение новых записей и переход к концу журнала.
- Потоковое чтение больших файлов и отмена длительных операций.
- Выбор кодировки, включая Windows-1251.
- Регулярные выражения и фильтры по времени, уровню события и другим полям.
- Редактирование существующего фильтра и временное отключение отдельных фильтров.
- Сохранение наборов фильтров между запусками.
- Несколько открытых файлов, поиск по отображаемому тексту и экспорт результата.

Перед реализацией каждой новой функции следует определить пользовательский сценарий,
правила взаимодействия с существующими фильтрами и проверяемые критерии приёмки.
